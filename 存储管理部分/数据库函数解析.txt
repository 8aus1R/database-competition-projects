__off_t lseek (int __fd, __off_t __offset, int __whence);
1.参数解析：
__fd：指文件的标识符（如文件句柄，它是标识和管理已打开文件的一个概念，用于操作文件时的引用，通过它，我们可以对文件进行读取、写入、关闭等操作）
__offset：基于_whence基准的偏移量
__whence：基准位置，有三个标准取值SEEK_SET：
SEEK_SET：以文件开头为基准，新偏移量 = __offset（__offset 必须 ≥ 0）。
SEEK_CUR：以当前偏移量为基准，新偏移量 = 当前偏移量 + __offset。
SEEK_END：以文件末尾为基准，新偏移量 = 文件总长度 + __offset（__offset 为正时可超出文件末尾，形成 “文件空洞”）。
2.返回值：
成功：返回调整后的新偏移量（以文件开头为起点，单位：字节）
失败：返回 -1
3.功能：
调整文件描述符的当前读写偏移量。一般用于文件读写时，定位到文件头，便于后续调用 read() 或 write() 时，会从这个新位置开始操作，并自动更新偏移量。
例如：off_t file_offset = lseek(fd, 50, SEEK_SET);
这里的偏移量为50，而SEEK_SET表示从fd文件开头开始，那么新偏移量就为50，那么接下来的read（）或者write（）操作都将从50字节开始。

int open (const char *__path, int __oflag, ...)；
1.参数解析：
__path：指向文件路径的字符串
__oflag：位掩码，指定打开文件的模式和选项（必选）。以下为打开模式和常用选项
打开模式（必选，互斥）
O_RDONLY：只读模式。
O_WRONLY：只写模式。
O_RDWR：读写模式。

常用选项（可选，可组合）
O_CREAT：若文件不存在则创建（需提供第三个参数指定权限）。
O_EXCL：与 O_CREAT 联用，若文件已存在则失败（避免竞态条件）。
O_TRUNC：若文件存在且为可写模式，将其长度截断为 0（清空内容）。
O_APPEND：写入时追加到文件末尾（自动更新文件指针到末尾）。
O_NONBLOCK：非阻塞模式（对设备或管道有效，读写立即返回而非等待）。
O_SYNC：同步写入（数据和元数据同步到磁盘，确保持久性）。
O_TMPFILE：用于创建一个匿名临时文件。这个文件没有文件名，也不会出现在文件系统目录中，但可以像普通文件一样读写，并且在关闭后会自动删除。

...：可变参数，仅在创建文件（O_CREAT 或 O_TMPFILE）时需要，用于指定文件权限（如 0644），以下是文件权限
所有基础权限宏的命名格式为：
S_<操作><用户类别>
操作：R（读）、W（写）、X（执行）。
用户类别：USR（所有者）、GRP（所属组）、OTH（其他用户）。
按 “用户类别” 分类如下：

所有者（User）权限宏
对应 “文件所有者” 的权限，与 S_IRUSR、S_IWUSR 同组：
S_IRUSR：User Read（所有者可读），对应权限位 r，数值 4。
S_IWUSR：User Write（所有者可写），对应权限位 w，数值 2。
S_IXUSR：User Execute（所有者可执行），对应权限位 x，数值 1。
组合示例：
S_IRUSR | S_IWUSR | S_IXUSR → 所有者有读、写、执行权限（rwx），数值 4+2+1=7（八进制 0700 的一部分）。

所属组（Group）权限宏
对应 “文件所属组” 的权限（组内用户的权限）：
S_IRGRP：Group Read（组可读），对应权限位 r，数值 4。
S_IWGRP：Group Write（组可写），对应权限位 w，数值 2。
S_IXGRP：Group Execute（组可执行），对应权限位 x，数值 1。
组合示例：
S_IRGRP | S_IWGRP → 组内用户有读、写权限（rw-），数值 4+2=6（八进制 0060 的一部分）。

其他用户（Others）权限宏
对应 “既不是所有者也不在所属组” 的用户的权限：
S_IROTH：Others Read（其他用户可读），对应权限位 r，数值 4。
S_IWOTH：Others Write（其他用户可写），对应权限位 w，数值 2。
S_IXOTH：Others Execute（其他用户可执行），对应权限位 x，数值 1。
组合示例：
S_IROTH → 其他用户仅有读权限（r--），数值 4（八进制 0004 的一部分）。

2.返回值：
成功：返回文件描述符（如 3、4 等，0、1、2 为标准输入 / 输出 / 错误）
失败：返回 -1
3.功能：
常用于打开已存在的文件或者创建新的文件。

std::scoped_lock lock{latch_};
1. 关键组件
std::scoped_lock
特性：
C++17 引入的通用锁管理类，支持多锁获取（防止死锁）。
构造时锁定所有给定的互斥锁，析构时释放。
latch_
通常是 std::mutex 或 std::shared_mutex 类型的成员变量，用于保护共享资源。

2. 功能概述
作用：在当前作用域内获取 latch_ 互斥锁，确保同一时间只有一个线程可以执行锁保护的代码块。
自动释放：std::scoped_lock 是 RAII（资源获取即初始化）类型，锁的生命周期与 lock 对象绑定。当 lock 离开作用域时（如函数返回或遇到 }），锁会自动释放。
例如：void addRecord(RmRecord record) {
        std::scoped_lock lock{latch_};  // 获取锁
        // 临界区：只有一个线程可执行此代码块
        records_.push_back(std::move(record));
    }  // 锁在此自动释放

3.如何判断是否需要锁
检查函数是否访问共享资源：如果只使用局部变量，通常不需要锁。
检查操作是否线程安全：如果操作涉及共享资源的读写，且不是原子（不可被中断的操作）的，需要锁。


std::unique_ptr 
1.功能：
是 C++ 标准库提供的一种智能指针，专门用于独占式管理动态分配的内存资源。
它的核心作用是：自动释放所指向的对象，避免内存泄漏，同时确保同一时间只有一个指针拥有该对象的所有权。
用一个例子理解：
假设你需要创建一个 RmRecord 对象（比如数据库中的一条记录），传统方式可能用裸指针：
// 裸指针方式（需要手动管理内存）
RmRecord* record = new RmRecord(100);  // 动态分配内存
// ... 使用 record ...
delete record;  // 必须手动释放，否则内存泄漏
如果忘记 delete，或者在释放前发生异常，就会导致内存泄漏。

而用 std::unique_ptr 则可以避免这个问题：
// unique_ptr 方式（自动管理内存）
std::unique_ptr<RmRecord> ret(new RmRecord(100));  // 独占所有权
// ... 使用 ret（通过 ret-> 访问成员） ...
// 无需手动 delete！当 ret 离开作用域时（比如函数结束），会自动释放内存

2.特性
-独占所有权：一个 unique_ptr 实例独占它所指向的对象，不能被复制（避免多个指针同时管理同一个对象），只能通过 std::move 转移所有权；
-自动释放资源：当 unique_ptr 离开作用域（比如函数返回、代码块结束）时，会自动调用 delete 释放所指向的对象，无需手动干预，从根源上避免内存泄漏；




std::make_unique
1.功能：
自动完成动态内存分配和 unique_ptr 的初始化，避免手动使用 new 带来的潜在风险
// 手动方式（C++11）
std::unique_ptr<RmRecord> ptr(new RmRecord(100));  // 先 new，再传递给 unique_ptr

// 使用 make_unique（C++14+）
std::unique_ptr<RmRecord>  ptr = std::make_unique<RmRecord>(100);  // 自动推导类型，无需重复写 RmRecord





事务：
1.含义：
事务（Transaction） 就是一组 “要么全做完，要么全不做” 的操作。事务的作用就是保证这组操作的 “完整性”，避免出现中间出错导致的数据混乱。
2.特性：
原子性（Atomicity）：“要么全成，要么全废”
原子性是事务的核心，意思是这组操作是 “不可分割” 的 —— 要么两个步骤都成功执行，要么两个都不执行，绝对不会出现 “只做了一半” 的情况。
比如转账时：
如果步骤 1 成功（A 扣了 100），但步骤 2 失败（B 没加 100），事务会 “回滚”（撤销步骤 1 的操作，A 的钱恢复原样），避免 A 的钱白白消失。
如果步骤 1 就失败（比如 A 余额不足），那步骤 2 根本不会执行，B 的钱不变。

 一致性（Consistency）：“操作前后，数据规则不变”
一致性指的是事务执行后，数据库的 “业务规则” 依然成立。比如转账的核心规则是 “总金额不变”（A 的钱 + B 的钱 = 总钱数）。
转账前：A 有 500，B 有 300，总金额 800。
转账后：A 有 400，B 有 400，总金额还是 800（规则成立）。
如果事务执行中出问题（比如 A 扣了 100 但 B 没加），总金额会变成 700（规则被破坏），这时候事务会回滚，保证一致性。

 隔离性（Isolation）：“多个事务同时执行，互不干扰”
如果多个事务同时操作数据库（比如你给 B 转账的同时，C 也给 B 转账），隔离性保证它们之间不会互相影响，就像 “各干各的” 一样。
比如：
你给 B 转 100（事务 1），C 给 B 转 200（事务 2）。
隔离性确保：要么事务 1 先执行完（B 先加 100，再加 200，最终 + 300），要么事务 2 先执行完（B 先加 200，再加 100，最终 + 300），不会出现 “B 只加了 200” 或者 “B 加了 400” 的错误。

持久性（Durability）：“一旦完成，结果就永久保存”
事务成功执行后，它对数据的修改会 “永久保存”，就算数据库崩溃、断电，重启后结果也不会丢失。
比如转账成功后：
即使银行系统突然断电，重启后 A 的余额还是 400，B 的余额还是 400，不会回到转账前的状态。



目录（文件夹）：数据库的元数据集合，记录数据库中所有对象（表、索引等）的原信息。我们目前遇到的是一个数据库对应一个目录的存储设计。

文件：每个数据库对象（表、索引）通常对应一个或多个文件。目前我们代码所体现的关系是一个表就对应一个独立文件，表的实际记录数据存储在以表名命名的文件中。一个文件包含多个页，是页的容器。

页：是数据库I/O的基本单位（磁盘读写必须按照页面划分）。一页包含多条记录；可被加载到内存帧中去。

记录：数据库中存储的最小逻辑数据单元，由多个字段组成。一条记录就是表的一行数据。如下就是一条记录：
+--------+------------+--------+
| id(4B) | name(10B)  | age(4B)|
+--------+------------+--------+
offset:   0           4        14

相互关系（包含关系如下）：
记录→页面→文件→目录

记录（Record）→ 页面（Page）
记录是逻辑数据单元，必须 “打包” 到页面中才能存储。一个页面可包含多条记录（数量取决于页面大小和记录大小），例如：8KB 的页面可存储 100 条 80 字节的记录。
页面内部有固定格式（如页头、记录区），页头记录页面元信息（如记录数、空闲空间地址）。

页面（Page）→ 文件（File）
页面是文件的最小物理单位，一个文件由多个页面组成。例如：一张表的所有记录被分散存储在其对应文件的多个页面中。

文件（File）→ 目录（Directory）
目录是数据库的 “索引”，记录每个文件对应的数据库对象（如表名→文件路径）、文件的页面分布、结构定义（如记录的字段类型、长度）等。例如：查询表user时，通过目录（数据库)找到user对应的文件路径，再定位到存储数据的页面。

一句话数据按 “记录打包到页面，页面组成文件，文件由目录管理” 的结构存储在磁盘。
