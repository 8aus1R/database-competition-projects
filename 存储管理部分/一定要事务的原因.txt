在 MySQL 中，即使没有显式开启事务，也可以执行 SQL 语句。但你的程序中如果不执行 txn_manager->begin() 就无法执行语句，是因为你的程序框架强制要求所有操作必须关联到一个事务上下文，这和 MySQL 本身的机制并不冲突，而是应用层的封装设计导致的。
1. MySQL 本身：默认支持 “无显式事务” 的语句执行
MySQL 默认处于 自动提交模式（autocommit=1）。在这种模式下，每条 SQL 语句会被自动包装成一个独立的事务：执行后立即自动提交（事务完成），无需手动调用 BEGIN 或 COMMIT。
 你的程序无法执行的原因：应用层的事务上下文依赖
你的代码中，context->txn_ 是程序与数据库交互的事务上下文。如果不执行 txn_manager->begin()，context->txn_ 可能未初始化（为空），而程序的封装逻辑强制要求：所有数据库操作必须关联到一个有效的事务上下文，即使底层 MySQL 支持无显式事务的执行。
锁与并发控制的依赖
数据库的锁机制（如行锁、表锁）通常与事务绑定：
事务开始后，锁的生命周期与事务一致（事务结束后释放）。
你的程序可能在执行 SQL 时需要申请锁，而锁的申请必须关联到一个活跃事务（否则无法确定锁的持有范围）。
如果 context->txn_ 未初始化，程序可能无法申请锁，导致 SQL 执行被阻塞或拒绝。
